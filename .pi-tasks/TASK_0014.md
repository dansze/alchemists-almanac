## refined prompt

Both files have the same bug. The Lua 5.1 sandbox does not support the `&` operator. OpenMW provides the `bit` library (LuaBitOp), which should be used instead.

**The fix** — in both `load-db.lua` and `init.lua`:

```
# load-db.lua line 101
BEFORE: if (me.flags and (me.flags & MGF_NO_MAGNITUDE)) == 0 then
AFTER:  if (me.flags and bit.band(me.flags, MGF_NO_MAGNITUDE)) == 0 then

# init.lua line 76
BEFORE: if (me.flags and (me.flags & MGF_NO_MAGNITUDE)) == 0 then
AFTER:  if (me.flags and bit.band(me.flags, MGF_NO_MAGNITUDE)) == 0 then
```

**Root cause:** Lua 5.1 (OpenMW's sandbox) does not have C-style `&` for bitwise AND. The `bit` library (LuaBitOp) is available in the OpenMW runtime and provides `bit.band(a, b)`.
