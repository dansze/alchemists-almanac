## 1. Lua 5.1 Sandbox Constraints

### 1.1 Base Lua Version

OpenMW runs **Lua 5.1** with the following extensions and restrictions.

### 1.2 Allowed Standard Libraries

| Library | Availability | Restrictions |
|---------|-------------|--------------|
| `coroutine` | ✅ Full | No restrictions |
| `math` | ✅ Partial | `math.randomseed` is **prohibited** (the engine sets it on startup) |
| `os` | ✅ Partial | Only `os.date`, `os.difftime`, `os.time` are available |
| `string` | ✅ Full | No restrictions |
| `table` | ✅ Full | No restrictions |
| `io` | ❌ Blocked | Not exposed |
| `file` | ❌ Blocked | Not exposed |
| `os.execute`, `os.remove`, etc. | ❌ Blocked | Not exposed |
| `debug` | ❌ Blocked | Not exposed |
| `package` | ❌ Blocked | Not exposed |

### 1.3 Allowed Basic Functions

All of the following are available in the sandbox:

```
assert, error, ipairs, next, pairs, pcall, print, select,
tonumber, tostring, type, unpack, xpcall, rawequal,
rawget, rawset, getmetatable, setmetatable
```

**Key implication:** `pcall` and `xpcall` are available, so mod authors should wrap risky API calls in `pcall` to prevent crashes. `error` can be used to raise Lua-level errors. `print` writes to the OpenMW console.

### 1.4 Supported Lua 5.2 Extensions

| Feature | Details |
|---------|---------|
| `goto` / `::labels::` | Full support |
| Hex string escapes | `\x3F` |
| `\*` escape in strings | In string literals |
| `math.log(x, base)` | Two-argument form added |
| `string.rep(s, n, sep)` | Three-argument form |
| `string.format` enhancements | `%q` is reversible; `%s` uses `__tostring`; `%a`/`%A` added |

| `__pairs` metamethod | Allowed; enables custom `pairs()` iteration |
| `__ipairs` metamethod | Allowed; enables custom `ipairs()` iteration |

### 1.5 Supported Lua 5.3 Extensions

| Feature | Details |
|---------|---------|
| UTF-8 library | All functions (`utf8.len`, `utf8.codes`, `utf8.gsub`, etc.) |

- In 0.51.0+: `LOAD` context scripts do **not** re-run after `reloadlua`; a full restart is required.
- Scripts restart with their `onSave`/`onLoad` handlers (simulating save/load cycle).

## 2. Serialization Limits for `onSave()` / `onLoad()`

### 2.1 Overview

OpenMW serializes Lua data for save games through `onSave()` and `onLoad()` callbacks.

- `onSave()` is called **before** the save is written. It **must return a serializable table**.
- `onLoad(data)` is called **after** the save is read. The `data` parameter is the value returned by `onSave()` from the saved game. If `data` is `nil`, this is a new game.

### 2.2 Serializable Types

The following types can be persisted across save/load cycles:

| Type | Example | Notes |
|------|---------|-------|
| `nil` | `nil` | Valid value; represents absence |
| Numbers | `42`, `3.14`, `-0.001` | All Lua numbers (double-precision floats) |
| Strings | `"hello"`, `"ingredient_001"` | UTF-8 encoded; length limited by serialization format |
| Game objects | (returned by `types.Ingredient.record()`, `world.getObjectByFormId()`, etc.) | References to engine-managed objects are serialized as form identifiers |
| `util.vector3` | `util.vector3(0, 0, 0)` | 3D vectors used for positioning; serialized as x, y, z components |
| Plain tables | `{"item1", "item2"}` or `{key = value}` | Only if all keys and values are themselves serializable |

### 2.3 Non-Serializable Types

The following types **cannot** be serialized and will cause save/load errors:

| Type | Why Rejected | Example |
|------|-------------|---------|
| Functions | Cannot be serialized; closures capture environment | `function() print("hi") end` |
| Custom metatables | Metatables may reference functions or other non-serializable data | `setmetatable({}, {__index = someFunc})` |
| Circular references | Serialization would loop infinitely | `local t = {}; t.self = t` |
| Multiple references to same table | Serialization ambiguity | `local t = {}; a = {t}; b = {t}` |
| Coroutines | Cannot be serialized | `coroutine.create(function() end)` |
| C userdata | C-level opaque handles (not game objects) | Results from C extensions |

### 2.4 Valid Save Data Patterns

**Pattern 1 — Simple flat table:**
```lua
function onSave()
    return {
        discoveredRecipes = 42,
        lastUsedKey = "L",
        settings = { immersiveMode = true },
    }
end
```

**Pattern 2 — List of string keys (ingredient IDs):**
```lua
function onSave()
    return {
        discoveredIngredients = {"slaughterfish_egg", "nightshade", "imp_stool"},
        encounteredMerchants = {"merchant_01", "merchant_02"},
    }
end
```

**Pattern 3 — Effect ID mappings (effect IDs as integers, ingredient IDs as strings):**
```lua
function onSave()
    return {
        version = 1,
        ingredientEffects = {
            ["slaughterfish_egg"] = {1, 3, 5},  -- effect IDs as numbers
            ["nightshade"] = {2, 4},
        },
    }
end
```

**Pattern 4 — Safe game object references:**
```lua
function onSave()
    local player = require('openmw.core').getObjectById('player')
    return {
        playerPosition = { player.x, player.y, player.z },
        lastVisitedCell = player.cell.name,
    }
end
```

### 2.5 Invalid Save Data Patterns

**Anti-pattern 1 — Storing functions:**
```lua
-- INVALID: functions cannot be serialized
function onSave()
    return {
        lookupFunc = function(ingredientId) return effects[ingredientId] end,
    }
end
```

**Anti-pattern 2 — Storing tables with metatables:**
```lua
-- INVALID: custom metatables cannot be serialized
local cache = setmetatable({}, {
    __index = function(t, key) return buildEntry(key) end,
})

function onSave()
    return { ingredientCache = cache }  -- FAILS
end
```

**Anti-pattern 3 — Circular references:**
```lua
-- INVALID: circular reference
local node = { value = 1 }
node.parent = node

function onSave()
    return { treeRoot = node }  -- FAILS
end
```

**Anti-pattern 4 — Multiple references to same table:**
```lua
-- INVALID: two references to the same table object
local shared = { key = "value" }
function onSave()
    return {
        left = { data = shared },
        right = { data = shared },  -- ambiguous serialization
    }
end
```

### 2.6 Safe `onLoad()` Patterns

**Pattern 1 — Handle `nil` data (new game):**
```lua
function onLoad(data)
    if not data then
        -- New game: initialize defaults
        discoveredIngredients = {}
        discoveredRecipes = 0
        return
    end

    -- Existing save: restore state
    discoveredIngredients = data.discoveredIngredients or {}
    discoveredRecipes = data.discoveredRecipes or 0
    if data.settings then
        immersiveMode = data.settings.immersiveMode or false
    end
end
```

**Pattern 2 — Reconstruct game objects from IDs:**
```lua
function onLoad(data)
    if not data then return end

    -- Reconstruct player position from saved components
    if data.playerPosition then
        local x, y, z = data.playerPosition[1], data.playerPosition[2], data.playerPosition[3]
        -- Player position reconstruction requires additional context
    end

    -- Reconstruct effect mappings from saved numeric IDs
    if data.ingredientEffects then
        for ingredientId, effectIds in pairs(data.ingredientEffects) do
            ingredientEffects[ingredientId] = effectIds
        end
    end
end
```

**Pattern 3 — Version-based migration:**
```lua
function onLoad(data)
    if not data then return end

    local version = data.version or 0  -- default to version 0 for old saves

    if version == 0 then
        -- Legacy format: migrate
        discoveredIngredients = data.ingredients or {}
        discoveredRecipes = data.recipes or {}
    elseif version == 1 then
        -- Current format
        discoveredIngredients = data.discoveredIngredients or {}
        discoveredRecipes = data.discoveredRecipes or 0
        immersiveMode = data.settings.immersiveMode or false
    else
        -- Unknown version: ignore save data, use defaults
        print("Warning: unknown save data version " .. tostring(version))
        discoveredIngredients = {}
        discoveredRecipes = 0
    end
end
```

### 2.7 Serialization of Game Objects

Game objects (returned by `types.Ingredient.record()`, `world.getObjectByFormId()`, etc.) have special serialization behavior:

| Aspect | Behavior |
|--------|----------|
| **Serialization** | Serialized as form ID strings or object references that the engine can resolve |
| **Deserialization** | The engine resolves them back to valid Lua object references on `onLoad()` |
| **Limitation** | If the referenced object has been deleted or the ESP unloaded, deserialization may return `nil` |
| **Safe practice** | Always check for `nil` after loading a saved game object reference |
| **Recommended** | Save form ID strings instead of object references when possible, then reconstruct with `core.getObjectById()` |

### 2.8 Serialization of `util.vector3`

`util.vector3` values serialize as three floating-point numbers (x, y, z):

```lua
-- Valid: save a position
local pos = util.vector3(100.5, -200.3, 50.0)
function onSave()
    return { position = pos }
end

-- onLoad: position is available as a vector3
function onLoad(data)
    if data and data.position then
        local x, y, z = data.position:x(), data.position:y(), data.position:z()
        -- or: local p = util.vector3(data.position:x(), data.position:y(), data.position:z())
    end
end
```

### 2.9 Key Constraints for Save Data Tables

| Constraint | Description |
|------------|-------------|
| **No functions** | Table values cannot be functions |
| **No metatables** | Tables cannot have custom metatables |
| **No circular refs** | A table cannot reference itself (directly or transitively) |
| **No duplicate table refs** | Two different table keys cannot point to the same table object |
| **Keys must be serializable** | Table keys must be `nil`, numbers, strings, or `util.vector3` |
| **Recursive depth** | Deeply nested tables may hit serialization limits; avoid excessive nesting |

### 2.10 Timer Serialization

Timers from `openmw.async` have built-in serialization behavior:

| Timer Type | Serialized |
|------------|-----------|
| `newSimulationTimer` | ✅ Yes — automatically saved/restored |
| `newUnsavableSimulationTimer` | ❌ No — lost on save/reload |
| `newGameTimer` | ✅ Yes — automatically saved/restored |
| `newUnsavableGameTimer` |
