CONTEXT
- `alchemy-ui.lua` already uses `openmw.ui` for all widget building (types, content, create), but it does not import or reference `openmw.interfaces.UI` anywhere — the file has no call to `require('openmw.interfaces').UI` or similar.
- The file's public API surface consists of exactly five methods on the returned `AlchemyUI` table: `create()`, `show()`, `hide()`, `destroy()`, `update(id)`.
- `AlchemyUI.hide()` is declared (line 108, called from `closeCallback`) but is never defined — the function body is missing, so the close button does nothing at runtime.
- Window creation (`AlchemyUI.create()` / `createPanel()`) uses `ui.create(layout)` from `openmw.ui` and stores the result in `panelState.panel`, with no explicit window title, name, or id property set on the layout.
- Visibility toggling in `AlchemyUI.show()` uses the pattern `panelState.panel.layout.layer = 'Windows'` to make the window appear — this sets a `layer` property on the panel's layout to the string `'Windows'`, then calls `panel:update()`.
- `AlchemyUI.hide()` is not implemented, so there is no corresponding `layer = nil` or layer-clearing logic — the window cannot be programmatically hidden after showing.
- `AlchemyUI.destroy()` calls `panelState.panel:destroy()` to destroy the widget, then resets `panelState.panel` to `nil` and `panelState.visible` to `false`.
- The module maintains `panelState` with fields: `panel` (widget ref), `contentPanel` (inner Flex ref), `visible` (boolean), and `currentId` (ingredient ID string).
- `AlchemyUI.update(id)` resolves ingredient effects via `db.ingredientEffects[id]` → `queryAndFormatEffects()` → `populateEffects(contentPanel, effects)`, and calls `AlchemyUI.show()` if not already visible.
- `alchemy-binding.lua` controls the toggle flow: `handleUI(val)` calls `alchemyUI.show()` when `not showing`, then `alchemyUI.hide()` when `showing` — it maintains its own `showing` state variable separately from `panelState.visible`.
- The binding file imports `openmw.ui` and `openmw.interfaces` but only uses `openmw.interfaces` for `Settings` registration — it never uses `openmw.interfaces.UI`.
- The `openmw.ui` package provides `ui.create(layout, options)`, `ui.content(table)`, `ui.screenSize()`, `ui.ALIGNMENT`, and `ui.TYPE` (Window, Flex, Text, Container, Widget) — all of which `alchemy-ui.lua` already consumes.
- The `openmw.interfaces.UI` interface (from `openmw.interfaces`) is a separate subsystem from `openmw.ui` — it provides higher-level window modes (`UI.MODE`, `UI.WINDOW`) that may handle window lifecycle differently than the low-level widget system.
- `AlchemyUI.show()` calls `ui.showMessage()` three times during creation/debugging — these are diagnostic calls that will remain after refactoring and should be preserved for behavioral equivalence.
- The `panelState.contentPanel` reference is obtained by walking the layout table indices (not by `name` lookup), meaning the inner Flex is identified by its position in `layout.content[1].content[2].content[1]` — this structural dependency must be preserved or re-examined.
- No window `name`, `id`, or `title` properties are set in the layout table — the window has no identifiable handle that other scripts could reference via name.
- `AlchemyUI.create()` is idempotent — if `panelState.panel` is already set, it returns early without rebuilding.
- `AlchemyUI.show()` is also idempotent — if `panelState.visible` is true, it returns early.
