## spec

GOAL
Add a module-level `CONFIG` table at the top of `scripts/alchemy-helper/alchemy-ui.lua` that exposes configurable positioning and theming for the alchemy effects panel. The config is a plain Lua table — no metatables, no classes — that modders can copy, paste, and edit directly. Positioning config (`corner` + `offsetX`/`offsetY`) determines the panel's screen-corner anchor (top-left, top-right, bottom-left, bottom-right; default: bottom-right) and its pixel offset from that corner. Theming config (`backgroundColor`, `titleColor`, `textColor`, `buttonColor`, `fontSizeTitle`, `fontSizeBody`, `padding`, `border`) drives visual appearance by merging into `openmw.ui` declarative layout-table props before `buildPanelLayout()` returns. `AlchemyUI.create()` reads the config from its own module scope (parameter-free). The existing `buildPanelLayout()` logic is not rewritten — the config is merged into its returned layout table by a thin post-processing step so the panel construction logic itself remains untouched.

CONSTRAINTS
- The API is declarative — positioning and theming are applied by merging config values into the declarative layout-table `props` subtables, NOT by calling imperative setter methods — the config must drive props in the layout table, do not use or invent imperative `setPosition`/`setAnchor` API calls [from: Q3]
- The configuration table is a module-level `local CONFIG = { ... }` at the top of `alchemy-ui.lua`, read inside `AlchemyUI.create()` which remains parameter-free — do not change the function signature [from: Q1]
- The config must be a plain Lua table using only strings, numbers, booleans, and nested plain tables — no custom metatables, classes, prototype chains, or function values [from: spec]
- Do not modify step 6's `buildPanelLayout()` function body — the config is injected by merging into the layout table after `buildPanelLayout()` returns, not by rewriting that function [from: spec]
- Do not modify step 7's alchemy menu detection or key binding mechanism in `alchemy-binding.lua` [from: spec]
- Do not touch step 9's save schema, `onSave()`/`onLoad()` handlers, or `onObjectAdded()` discovery wiring [from: spec]
- Do not touch step 10's `pcall` guards or error handling logic [from: spec]
- The `openmw_aux.ui` API contract from step 6 must remain unchanged — positioning/theming works entirely by merging into declarative layout-table props before the layout is passed to `openmw_aux.ui` primitives; no additional imperative API surface is introduced or modified [from: spec]
- The configuration table must be keyed by stable, documented names — do not invent undocumented keys or rely on internal implementation details of `openmw.ui` primitives [from: spec]
- If the alchemy menu is not detected, fall back gracefully to a default screen-corner position rather than crashing [from: spec]
- Support all four screen corners (top-left, top-right, bottom-left, bottom-right) with `corner` defaulting to `"bottom-right"` to match typical OpenMW inventory panel placement [from: Q2]

ACCEPTANCE
- `scripts/alchemy-helper/alchemy-ui.lua` contains a module-level `local CONFIG = { ... }` before any function definitions. The table has two top-level sub-tables: `CONFIG.positioning` and `CONFIG.theme`.
- `CONFIG.positioning` contains: `corner` (string: `"top-left" | "top-right" | "bottom-left" | "bottom-right"`, default `"bottom-right"`), `offsetX` (number, default `50`), `offsetY` (number, default `50`).
- `CONFIG.theme` contains: `backgroundColor` (number or `nil`, nil = engine default), `borderColor` (number or `nil`), `titleColor` (number or `nil`), `textColor` (number or `nil`), `buttonColor` (number or `nil`), `fontSizeTitle` (number, default `16`), `fontSizeBody` (number, default `12`), `padding` (number, default `5`), `margin` (number, default `2`), `border` (boolean, default `true`).
- `buildPanelLayout()` is NOT rewritten — its body is preserved verbatim. A thin `applyConfigToLayout(layout, config)` function (or equivalent inline logic) merges `CONFIG` values into the layout table after `buildPanelLayout()` returns, modifying `props.x`, `props.y`, `props.fontSize`, `props.backgroundColor`, `props.borderColor`, `props.padding` as applicable.
- The corner-to-(x, y) mapping is deterministic: `"bottom-right"` → panel placed at `(screenWidth - panelWidth - offsetX, screenHeight - panelHeight - offsetY)`; `"bottom-left"` → `(offsetX, screenHeight - panelHeight - offsetY)`; `"top-right"` → `(screenWidth - panelWidth - offsetX, offsetY)`; `"top-left"` → `(offsetX, offsetY)`. Screen dimensions use available OpenMW APIs or a reasonable assumption (e.g. 1920×1080) when not queryable.
- When `corner` holds an unrecognized string value, the implementation falls back to `"bottom-right"` without error.
- When any `theme` property is absent or `nil`, the corresponding layout-table prop is left untouched (preserves `buildPanelLayout()` defaults).
- The existing `AlchemyUI.create()`, `AlchemyUI.show()`, `AlchemyUI.hide()`, `AlchemyUI.destroy()`, `AlchemyUI.update()` public signatures are unchanged (zero new parameters).
- All values in `CONFIG` are serializable plain Lua types (strings, numbers, booleans, plain nested tables), consistent with SANDBOX_CONSTRAINTS.md §8.
